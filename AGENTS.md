## Build

- `zig build` — compile (Zig >= 0.16.0
- `zig build run` — build + run (kills running game.exe first, Windows-only)
- `zig build test` — unit tests on `exe_mod` (transitive tests from `src/main.zig`)
- `zig build -Dtracy_enable=true` — enable Tracy; `-Dtracy_callstack=N` (default 10)
- Default target ABI is forced to `.gnu` (`build.zig:7`)
- `genFileNameIdHashMap` auto-runs as a build dep → regenerates `src/fileSystem/fileNameID.zig`. Do not edit by hand.

## Zig 0.16.0 使用笔记 (参考 src/loadmap/loadmap.zig)

- `@ptrCast(slice)`：`std.mem.readInt` 参数是 `*const [4]u8`，把 `[]u8` 切片用 `@ptrCast` 转换：`std.mem.readInt(u32, @ptrCast(mem[offset .. offset + 4]), .native)`
- `@alignCast` + `bytesAsSlice`：`gpa.alignedAlloc(u8, .of(T), n)` 返回 `[]align(N) u8`（0.16 新 `Alignment` 类型，`null` 表示 T 的自然对齐）；`std.mem.bytesAsSlice` 保留指针对齐属性，需 `@alignCast` 降为自然对齐的类型化切片：
  ```zig
  const memory = try gpa.alignedAlloc(u8, .of(GridLayer), totalLen);
  const layers: []GridLayer = @alignCast(std.mem.bytesAsSlice(GridLayer, layersBytes));
  ```
- `std.mem.readInt` 直接返回 `T`（非 error union），不需要 `try`；`alignedAlloc` 才需要 `try`
- grid 在层数组中的定位：差值先 `@intCast` 到 `u32` 再除 `gridLength`（层 `leftUp` 是层内最小坐标，差值必非负），商直接作切片索引（`u32` 索引合法）：
  ```zig
  const gx = @as(u32, @intCast(x - layer.leftUp[0])) / layer.gridLength;
  const gy = @as(u32, @intCast(y - layer.leftUp[1])) / layer.gridLength;
  const grid = &layer.grids[gy * layer.col + gx];
  ```

## Content pipeline (watcher)

The main workflow uses the **watcher** binary (`watcher/`, its own `build.zig`, Zig >= 0.16.0). It hot-reloads on file change:

- `zig build run` (from `watcher/`) starts the watcher
- It reads `.watching` to know which dirs to watch (`Shaders`, `Sampler`, `pipeline`, `zig-out\bin\Content`)
- On change, it automatically:
  - Compiles GLSL → SPIR-V (uses embedded `shaderc_combined`, no external `glslc` needed)
  - Re-parses affected pipeline `.pipe` files → `.pipeb` (traverses shader-pipeline graph in DB)
  - Parses sampler `.samp` files → `.sampler`
  - Updates content DB (`Content.db`) for files in `Content/` folder
- Ctrl+C exits, Ctrl+Break force-saves DB without exiting
- `-force` flag re-processes everything from scratch

The batch scripts in `build_script/` (`shaderCompile.bat`, `pipelineParse.bat`, `samplerParse.bat`) are the **manual fallback** — they need `glslc.exe` on PATH and a file list generated by `selectModifiedFileToTxt`.

## Architecture

- **Entrypoint**: `src/main.zig` spawns update + render threads, inits SDL3 + Vulkan + Tracy
- **Module convention**: Each significant source file is its own Zig module in `build.zig`. Import by module name (e.g. `@import("video")`, `@import("fileSystem")`), not file path
- **Vulkan core**: `src/video/VkStruct.zig` (~1850 lines) — device/swapchain/descriptors/gfx pipeline. `src/video/processRender.zig` — per-frame rendering
- **Render graph**: DAG-based pass system in `monsoon/pass/` (`PassImp.zig`, `renderFlow.zig`). DAG debug flags in `monsoon/global.zig` (`printDagToDot`, `stopNodeDagPrint`)
- **Pass pipeline 声明/运行时模型**: schema 层 `monsoon/pass/Pass.zig` `Pass.Pass.pipeline: ?[]Pipeline`(nullable 列表,每条含 `{name, isMesh}`;`null` = 未声明管线,PassImp 会跳过该 pass 不进 runtime)。`renderFlow.addPipelineToPass(passName, pipe)` 将单条 pipeline **追加**到该列表(arena realloc 扩容),`createPass` 初始为 `null`。运行时层 `PassImp.Pass.pipeline: []Pipeline_t`,在 `initFromRenderFlow` 中按声明列表逐条 `readPipelineFileAndAdd`(deinit 需 `gpa.free`);各 vtable 的 addCommand(setPass 等)通过 `pass.pipeline[i]` 按索引绑定管线命令字段(当前每 pass 均恰好 1 条,固定取 `pass.pipeline[0]`)。push constant 同构:schema `Pass.Pass.pushConstant: []PushConstantPack`,每次 `renderFlow.setPushConstant(passName, stage, size)` **追加**一条 range(arena realloc);运行时 `PassImp.Pass.pushConstant: []PushConstantPack`,每个元素在 `initFromRenderFlow` 单独 `gpa.alloc` 一块 `size` 的 `pValues` 缓冲(deinit 逐元素 free 后 free 数组);`PassImp.Pass.setPushConstants(index: u32, mem, offset)` 按索引写某个 pack 的 `pValues`(索引与 pipeline/pushConstant 数组对齐;数组空时 panic),命令绑定及直写 `pValues` 的代码按需取 `pass.pushConstant[i]`
- **Merged pass `i_feather`(src/setPass.zig)**: 将原 `c_command_prefix_sum`→`ic_task`→`iv_feather` 三段流水合并为单一运行时 pass "i_feather",顺序 fill+compute(前缀和)→ fill+computeIndirect → drawIndirect;三条 pipeline/pushConstant 按索引区分(0=c_commandPrefixSum.pipeb compute 16B、1=ic_task.pipeb compute 52B、2=iv_feather.pipeb vertex 68B)。buffer 索引表见 `const IF`(drawCommands=0、meshStorage=1、meshlet=2、vertices=3、meshletVertices=4、meshletTriangles=5、featherCommands=6、dispatchCommands=7、groupMappings=8、instance3D=9、meshes=10、payloads=11、params=12);init 直写 `pass.pushConstant[1]/[2].pValues`,`setPushConstants(0,…)` 写 pack0。描述符集用**超集** `[globalTextureDescriptorSet, global3dMVPMatrixDescriptorSet]`,compute 命令绑 `pass.descriptorSet[0..1]`、draw 绑全量。外部引用:render.zig 用 `passMap.get("i_feather")`(instance3D=9、passGroupMapping.upload 目标 buffer[6]=featherCommands / buffer[8]=groupMappings);instances.zig 每帧 `item.pass.setPushConstants(2, toBytes(tidx), 64)` 写 iv 段纹理索引。注意 `ic_Task_PushConstant` 是 extern struct(注册 52B,sizeof 56B,沿用旧行为),`Iv_feather_PushConstant` 注册用 `@sizeOf`(72B)
- **ECS**: `src/ecs.zig` (thin wrapper over `src/ecs/`)
- **Content DB**: SQLite database (`Content.db`) tracking all assets — managed by the watcher at dev time, read by the engine at runtime
- **Handle system**: `src/handle/handle.zig` — 10240 handles with `Once` reuse
- **Resource readers**: every `processResource` (`*_Reader` in `src/resourceProcess/{binary,ktx2,lMap,png,vtx,instance}.zig` + `Example_Reader` in `src/resourceProcess.zig`) shares the uniform signature `(comptime fType: ProcessType, ctx: *const resource.ResourceCtx, sqlite: sqlite3, fileID: i32, handle: Handle, buffers: ?[]Buffer_t, commands: *ExternalCommands, uctx: *Ctx) !u32`. Params overlapping `resource.ResourceCtx` (`io/gpa/vulkan/handles`) were removed and are re-extracted at the top of each fn (`const io = ctx.io; …`); `sqlite` stays an explicit param on purpose (per-worker pooled DB connection, thread safety); dispatched from `monsoon/resource.zig` worker via `args.ctx`. Error convention: on failure readers `std.log.err` then **return `Handles.WaitFill`** (do not propagate `err`)
- **Instance reader**: `src/resourceProcess/instance.zig` `Instance_Reader` reads `.instance` JSON (`Assets/schema/instance.schema.json`) via `std.json.parseFromSlice`; layout root `{items:[…]}` with optional `"$schema"` field on the `File` struct (no `ignore_unknown_fields`); item = `{pass, pos, scale, rotation: f32 arrays, textures: []string, model?: string}`. Fill loop: `pos/scale/rotation` must be length 3 (else `ResourceError.Invalid`, copied into `vec3`), `pass` looked up in `ctx.passes.passMap` (else `Invalid`), `textures` name→handle via `uctx.pTextureSet.getTexture(file.getID(name))` (else `Unavaliable`), `model` via `resource.getResourceHandle(file.getID(name))` (else `Unavaliable`). Then each item is pushed with `uctx.instances2.add(io, ins)` (add failure → log + `Handles.WaitFill`). **Texture handle arrays are allocated from `uctx.instances2.instances.allocator`** (ownership moves to instances2; freed in `monsoon/instances/instances.zig` `load()` before `clearRetainingCapacity`)
- **Pipeline schema**: `schema/pipeline.schema.json` (JSON Schema draft-2020-12) documents the `.pipe` format; enums unconstrained (plain strings), unknown fields allowed
- **Sampler schema**: `schema/sampler.schema.json` (JSON Schema draft-2020-12) documents the `.samp` format (flat VkSamplerCreateInfo, integer enums); same permissive policy as the pipeline schema
- **Scene schema**: `Assets/schema/scene.schema.json` (JSON Schema draft-2020-12) — top-level **array** of placed instances, each an object `{pass: string, pos/scale/rotation: number arrays, textures: string array}` (all required) with optional `model: string`; unknown fields rejected (`additionalProperties: false`). Example: `Assets/scene/test.scene`
- **LoadMap schema**: `Assets/schema/loadmap.schema.json` (JSON Schema draft-2020-12) documents recursive grid loadmap format; `gridLength` required everywhere, `leftUp` required in grids, `items` entries are `{name, isGpu, bufferName(optional string array)}` objects (`name`/`isGpu` required), `passes` string array in root and grids, `depth` is a non-negative parsing-limit-only int, unknown fields rejected (`additionalProperties: false`)

## lMap binary format

```
| magic | depth | totals (5) | offsets[] | layer0 | layer1 | ... |
```

- `magic` 4B: ASCII `"lMap"`
- `depth` 4B: grid layer count — file contains `depth + 1` layers (root layer included)
- `totalGridCount` 4B u32 — Σ per-layer `row × col` (spatial grid slots, NOT written grids); reader uses it to size the grids memory region without traversal
- `totalItemCount` 4B u32 — number of items
- `totalPassCount` 4B u32 — number of passes
- `totalU8Count` 4B u32 — number of u8
- `totalBufferNameCount` 4B u32 — total number of bufferName strings across all items
- `offsets`: `(depth + 1) * 4B` — file offset where each grid layer starts (header is 28B + offsets)
- **Grid layer** (all grids of the same depth stored together):
  - `gridRow` 4B — grid row of this layer
  - `gridCol` 4B — grid col of this layer
  - `leftUp` 8B — layer min (x, y) across its grids (written after the loop, like row/col)
  - `gridLength` 4B — grid size of this layer
  - `gridCount` 4B u32 — number of **non-blank** grids written for this layer; the layer's in-memory spatial array is `row × col`, blank slots keep struct defaults
  - Grid × `gridCount`:
    - `leftUp` 8B — (x, y) coordinates; locates the grid's slot in the layer array: `idx = (y - layerLeftUp.y) / gridLength * col + (x - layerLeftUp.x) / gridLength`
    - `itemCount` 4B
    - Item × `itemCount`:
      - `nameLen` 4B, then `name` bytes
      - `isGpu` 1B
      - `bufferNameCount` 4B, then per name: `bufferNameLen` 4B, then `bufferName` bytes
    - `passCount` 4B
    - Pass × `passCount`: `passLen` 4B, then `pass` bytes
